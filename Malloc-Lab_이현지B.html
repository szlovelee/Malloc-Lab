01 · 논리적으로 효과를 설명할 수 있는 개선

공간과 작업 줄이기

구현한 개선효과의 근거
할당 블록의 footer 생략
GET_PALLOC(HDRP(ptr))
이전 블록이 free일 때만 footer가 필요
할당 블록의 메타데이터 저장 공간 감소
best-fit의 상위 클래스 탐색 중단
if (!cur && best) return best;
후보를 찾은 클래스의 검사를 마치면
더 큰 클래스에는 더 작은 후보가 없음
realloc을 제자리에서 확장
if (sum >= blocksize) return ptr;
뒤의 가용 블록과 합쳐 충분하면
새 할당과 기존 payload 복사를 생략

02 · 경험적으로 선택한 정책

요청 패턴에 맞춘 휴리스틱

적용한 정책과 코드 요약효과를 기대한 이유
2의 거듭제곱에 가까운 요청 보정
size_t upper = 32;
while (upper < size) upper <<= 1;
if (size >= upper - upper / 8)
  return TO_BSIZE(upper);
요청 이상인 최소 2의 거듭제곱을 찾고,
그 값의 7/8 이상이면 상한 크기로 보정
해제 후 조금 더 큰 요청에도 재사용 가능112 B 요청: upper = 128, 블록 = 136 B
중간 크기 요청은 여러 개 분량 확보
batch_size = size * 8;
비슷한 요청이 반복되면 힙 확장 횟수 감소
요청 단위에 맞춰 잔여 공간의 배치 조정
초기 가용 공간은 작게 확보
initial = mem_sbrk(64);
초반의 작은 요청을 처리할 여유를 두면서
처음부터 크게 확보하는 낭비를 줄임
요청 비율에 따라 앞·뒤 분할
requested < blocksize / 2
잔여 공간의 위치와 병합 기회를 조정
실험했지만 개선 효과는 일정하지 않았음
효과는 요청 패턴에 따라 달라짐 · 8배, 64 B, 분할 기준은 실험으로 선택04 / 05
